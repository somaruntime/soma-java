# Compiler integration 契约

状态：正式设计文档
Owner：`soma-processor`
事实范围：`@SomaValue` source lowering、javac integration、processor phase ordering、supported compiler/build boundary 和 fail-closed behavior
非事实范围：annotation logical semantics、generated API behavior、normalized schema/hash、runtime storage 和 IDE 产品实现
最后审查日期：2026-07-10

## 1. 目标

本文回答普通 JSR 269 processor 无法单独回答的问题：SOMA 如何让未显式声明 modifiers/constructor 的 `@SomaValue`，在用户源码、processor 和 generated companion 中表现为同一个 immutable effective type。

`@SomaValue` 的 logical shape 由 [annotation schema 契约](../../soma-annotations/docs/annotation-schema-contract.md) 拥有；normalization/diagnostics 由 [Schema processing 契约](schema-processing-contract.md) 拥有；generated artifact 由 [Code generation 契约](code-generation-contract.md) 拥有。本文只拥有 compiler boundary。

## 2. 已接受的 V1 机制

V1 使用两个协作组件：

```text
javac 8 parse
  -> SOMA javac plugin：在 Enter 前完成 @SomaValue effective-type lowering
  -> javac symbol enter
  -> JSR 269 processor：collection / validation / normalization / hash / codegen
  -> attribution / flow / class generation
```

两个组件随 `soma-processor` build-time artifact 发布：

- `com.sun.source.util.Plugin` provider 负责 parse-phase source lowering；
- `javax.annotation.processing.Processor` provider 负责普通 annotation processing；
- runtime artifact 不包含或加载 compiler integration；
- application 必须同时启用 transformer 和 processor，不能只启用其中一个。

不采用以下替代方案：

- 用 `Filer` 重新生成与输入类同名的 source；
- processor round 完成后再尝试只改 AST flags；
- runtime reflection/bytecode generation 补救缺失的 immutable semantics；
- 退化为 public `XxxRecord` companion 以绕过 schema class materialization；
- 在 transformer 不可用时静默按 mutable Java class 编译。

## 3. Lowering contract

Transformer 对合法 `@SomaValue` declaration 产生以下 effective shape：

- class effective `final`；
- 每个 annotated instance field effective `public final`；
- canonical all-fields constructor；
- canonical value `equals()` / `hashCode()`；
- deterministic `toString()`；
- 不生成 setter 或 mutable escape hatch。

Lowering 必须在 symbol enter 前完成，使以下参与者看到同一类型：

- 同一 compilation unit 中的用户代码；
- 其他 compilation unit；
- JSR 269 element/tree model；
- generated companion source；
- classfile consumer。

Transformer 不能自行改变 field order、logical name、leaf expansion、default、selector 或 schema hash input。它只能实现 annotation contract 已经声明的 effective Java shape。

## 4. 冲突与失败

用户声明与 implicit member 冲突时必须 fail closed：

- explicit constructor 与 canonical constructor signature 冲突；
- explicit `equals()` / `hashCode()` 与 canonical value semantics 冲突；
- explicit `toString()` 与 deterministic generated form 冲突；
- field modifier、initializer、static/transient/volatile shape 与 value contract 冲突；
- inheritance、nested/local/anonymous shape 不被 annotation contract 支持；
- transformer 未运行、运行顺序错误或 processor 看不到 lowered shape；
- compiler identity 不在 supported matrix 中。

失败必须产生 stable processor/compiler diagnostic code，并阻止 schema-specific artifact 成为可用输出。不得只产生 warning 后继续编译 mutable/partial effective type。

## 5. V1 compiler baseline 与 support-matrix 边界

V1 的 source/runtime baseline 与 compiler baseline 分开描述。下表是技术基线，不是已经通过的 G6 vendor/minor、OS 和 architecture support matrix：

| 维度 | V1 contract |
|---|---|
| Java source level | Java 8 |
| generated bytecode target | Java 8 |
| runtime JVM | Java 8 bytecode/runtime contract；具体 vendor/build 只由 G6 release matrix 证明 |
| source transformer | javac 8 plugin adapter |
| annotation processing | JSR 269 on the same javac 8 invocation |
| canonical build | Maven Wrapper + Maven Compiler Plugin + full JDK 8 |
| JRE-only build | 不支持；compiler integration 需要完整 JDK |
| JDK 9+ javac | 不由 javac 8 adapter 支持；新增 adapter 和 gate evidence 后才能声明 |
| ECJ/Eclipse compiler | V1 不支持 |
| Gradle/Ant/direct javac | 未经独立 consumer fixture 证明前不声明支持 |

实施阶段先以当前开发机的完整 JDK 8 javac、Maven Wrapper 和当前 OS/architecture 作为开发与验证基线。每次 compile/golden/external-consumer validation 必须记录实际 JDK vendor/version/build、OS、architecture 和命令；本机通过只表示该环境通过，不能借用“Java 8”名称自动升级为其他组合的 supported claim。

正式 JDK vendor/minor、runtime JVM、OS 和 architecture support matrix 是 G6 required evidence。在 public RC/release sign-off 前未确定并验证时，matrix item 必须保持 `not-started` 或 `blocked`，不得从 V1 删除，也不得用本机 package smoke 替代。

### 5.1 IDE boundary

Maven/javac build 是 V1 compilation authority。

- IDE 委托 Maven build 时，必须得到与命令行相同的编译结果；
- IDE editor/JPS/ECJ semantic model 若不能加载同一 transformer，不得被描述为完整支持；
- autocomplete、synthetic constructor navigation、inline diagnostics 等 editor experience 只有在专用 IDE adapter/plugin 通过独立 gate 后才能声明；
- IDE 红线或提示不能覆盖 Maven package smoke 的编译事实，反之 Maven 编译成功也不能被写成“IDE code insight 已支持”。

## 6. Maven activation contract

Consumer build 至少提供：

- `soma-annotations` compile dependency；
- `soma-runtime-core` runtime/compile dependency；
- `soma-processor` build-only dependency；
- processor artifact 位于 javac plugin discovery path；
- `-Xplugin:<stable-soma-plugin-name>`；
- processor path/discovery；
- Java 8 source/target 和 UTF-8。

Stable plugin name、processor class name 和最终 Maven snippet 必须由 first external-consumer fixture/golden 固化。实现前文档可以使用 symbolic name，但 G4 之前必须替换为真实 artifact/class/plugin identifiers。

Processor artifact 不得成为 application runtime transitive dependency。Compiler internal packages 不得从 generated/public API 泄漏。

## 7. Processing rounds and incremental build

- lowering 对每个 parsed declaration 最多执行一次；
- processor round 必须检测 duplicate collection，不重复生成 artifact；
- generated source 只读取 validated normalized model；
- schema dependency change 必须使受影响的 generated artifact 重新生成；
- deleted/renamed schema 不得留下可被 package smoke 误用的 stale generated source；
- release/golden evidence 使用 clean build；
- incremental build 只有在 clean 与 incremental 输出逐文件等价后才能成为 supported claim。

V1 不把 IDE incremental compiler 的非标准 round behavior 当作 canonical processing model。

## 8. Determinism and compatibility identity

Compiler integration identity 至少包含：

- transformer protocol version；
- adapter id；
- supported javac family；
- processor version；
- lowering semantic version。

改变 implicit field/member shape、constructor、value equality/hash 或 lowering order，必须改变 processor/runtime compatibility identity，并进入 public compatibility review。Compiler vendor/minor 可以只进入 evidence metadata，除非它改变 normalized/generated result。

## 9. Evidence obligations

G2/G4 至少覆盖：

- standard Filer 不能替换 initial input type 的 negative fixture；
- transformer 缺失时 fail closed；
- same-unit 和 cross-unit constructor/field access；
- class final、field public-final、canonical constructor 的 classfile inspection；
- final field mutation compile failure；
- equality/hash/toString golden；
- processor element model 看到 effective shape；
- generated companion 使用 effective constructor/type；
- clean/incremental output comparison；
- Maven external consumer package smoke；
- unsupported compiler/JDK diagnostic；
- Java 8 runtime execution。

2026-07-10 的 feasibility evidence 记录在 [compiler integration spike report](../../reports/2026-07-10-compiler-integration-spike-report.md)。该报告只证明最小 lowering 机制，不替代完整 G2/G4。

## 10. 演进边界

未来支持 JDK 17/21/其他 javac family 时，应先新增 compiler adapter 和 matrix lane；pure normalization/codegen 不应复制到 adapter。若 adapter 数量或独立发布周期形成真实边界，再考虑拆分模块，不能在只有一个 adapter 时预先制造空模块。

新增 IDE/ECJ/Gradle integration 是新的 tooling capability，不得通过放宽 `@SomaValue` immutable contract 来实现。

## 11. 非目标

本文不承诺 cross-JDK internal API stability、所有 IDE code insight、ECJ、Kotlin、Gradle、runtime instrumentation、classfile post-processing 或用户手写 Lombok annotation 互操作。
